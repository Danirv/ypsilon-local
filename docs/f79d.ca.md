# Perfil Runxin F79D

Aquest document recull el coneixement del dispositiu F79D utilitzat per Ypsilon. Els ids, codecs i evidències són a `runxin/fields.py`; `runxin/f79d.py` construeix les trames i descodifica l'estat.

## Llegenda d'evidències

- **A** — present al codec/camps de l'aplicació WaterDevice antiga;
- **O** — valor o comportament observat al Ypsilon/F79D real del projecte;
- **HW** — escriptura local executada d'extrem a extrem i confirmada mitjançant una lectura local independent;
- **CW** — canvi de valor observat mitjançant l'aplicació cloud antiga.

`A` no implica que tots els firmwares o rebrands F79D implementin el camp de manera idèntica.

## Semàntica del patró de treball

L'aplicació WaterDevice antiga conté un enum explícit per al camp 9. Ypsilon exposa el mateix mapping com a enum de Home Assistant de només lectura:

| Raw | Estat estable | Etiqueta de l'app antiga |
|---:|---|---|
| 0 | `downflow_meter_delayed` | DF Meter delayed |
| 1 | `downflow_meter_immediate` | DF Meter immediate |
| 2 | `downflow_intelligent_meter_delayed` | DF Intelligent meter delayed |
| 3 | `upflow_meter_delayed` | UF Meter delayed |
| 4 | `upflow_meter_immediate` | UF Meter immediate |
| 5 | `upflow_intelligent_meter_delayed` | UF Intelligent meter delayed |
| 6 | `filter_type` | Filter type |
| 7 | `meter_delayed` | Meter delayed |
| 8 | `meter_immediate` | Meter immediate |
| 9 | `intelligent_meter_delayed` | Intelligent meter delayed |

Els codis 0..6 també són coherents amb les famílies publicades per Runxin de flux descendent, flux ascendent i filtre. La integració no exposa el camp 9 com a escriptura: conèixer un encoding legacy no és suficient per considerar segur un ajust mecànic.

## Escriptures verificades en maquinari

Confirmades mitjançant SET local + lectura local independent: **4, 6, 7, 10, 43 i 47**. Continuen pendents **34 (forçar regeneració)** i **49 (mode vacances)**.

## Reconstrucció de volums

Els camps 35, 37, 39 i 41 necessiten el camp de continuació immediatament posterior:

```text
value = (continuation_high
         + continuation_low * 100
         + base_high * 10000) / 100
```

El byte baix del camp base no participa en aquesta fórmula. Per al `waterVolumeUnit = 2` verificat al projecte, els valors resultants s'expressen en metres cúbics. El camp 11 és un valor separat de cabal instantani de servei en centèsimes; amb el codi d'unitat 2 s'exposa en metres cúbics per hora.

## Regeneració

`regenerationPattern` representa el criteri general de regeneració:

- `0`: per comptador / volum;
- `1`: per temps / dies.

`workPattern` representa l'estratègia concreta del controlador descrita més amunt. Per tant, tots dos camps són complementaris i no equivalents.

A l'equip del projecte el mode normal és per volum. `residualWaterProduction` és capacitat de tractament restant, no aigua emmagatzemada físicament. `operationDay` i `remainingDay` són principalment rellevants en el mode temps/dies.

El payload cloud legacy també conté `regenerationTimes`, però no s'ha demostrat cap mapping local F79D. Ypsilon no n'inventa cap ni exposa una entitat local derivada.

## Semàntica d'estadístiques de Home Assistant

Les classes d'estat s'assignen segons el model actual de sensors de Home Assistant:

- `flowRate` — `measurement`: lectura de cabal del moment actual;
- `dailyWaterConsumption` — `total_increasing`: total diari acumulat que es pot reiniciar quan comença un nou cicle;
- `residualWaterProduction` — `measurement`: capacitat restant actual;
- `averageWeeklyWaterConsumption` — sense `state_class`, perquè ja és una agregació històrica;
- `periodicWaterProduction` — sense `state_class`, perquè és una quantitat periòdica/configurada proporcionada pel controlador i no una mesura actual ni un comptador acumulatiu.

Això evita demanar a Home Assistant estadístiques a llarg termini enganyoses sobre valors ja agregats o de tipus configuració.

## Superfície segura d'escriptura de Home Assistant

El codec coneix més encodings dels que HA exposa. El servei administrador és deliberadament més restrictiu. No s'ha d'afegir un camp només perquè l'aplicació antiga tingui encoder: una trama sintàcticament vàlida pot canviar un paràmetre mecànic insegur.

## Camp 52

La consulta normal llegeix 1..51. El camp 52 es consulta per separat i es cacheja durant una hora a la capa Ypsilon; no forma part del contracte genèric de transport Runxin.
