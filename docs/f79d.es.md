# Perfil Runxin F79D

Este documento recoge el conocimiento del dispositivo F79D usado por Ypsilon.
Los ids, codecs y evidencias están en `runxin/fields.py`; `runxin/f79d.py`
construye las tramas y decodifica el estado.

## Leyenda de evidencias

- **A** — presente en el codec/campos de la aplicación WaterDevice antigua;
- **O** — valor o comportamiento observado en el Ypsilon/F79D real del proyecto;
- **HW** — escritura local ejecutada de extremo a extremo y confirmada mediante
  una lectura local independiente;
- **CW** — cambio de valor observado mediante la aplicación cloud antigua.

`A` no implica que todos los firmwares o rebrands F79D implementen el campo de
forma idéntica.

## Escrituras verificadas en hardware

Confirmadas mediante SET local + lectura local independiente: **4, 6, 7, 10,
43 y 47**. Siguen pendientes **34 (forzar regeneración)** y **49 (modo
vacaciones)**.

## Reconstrucción de volúmenes

Los campos 35, 37, 39 y 41 necesitan el campo de continuación inmediatamente
posterior:

```text
value = (continuation_high
         + continuation_low * 100
         + base_high * 10000) / 100
```

El byte bajo del campo base no participa en esta fórmula.

## Regeneración

`regenerationPattern`: `0` = volumen/caudal; `1` = tiempo/días. En el equipo del
proyecto el modo normal es por volumen. `residualWaterProduction` es capacidad
de tratamiento restante, no agua almacenada físicamente.

## Superficie segura de escritura de Home Assistant

El codec conoce más encodings de los que HA expone. El servicio administrador
es deliberadamente más restrictivo. No debe añadirse un campo solo porque la
aplicación antigua tenga encoder: una trama sintácticamente válida puede cambiar
un parámetro mecánico inseguro.

## Campo 52

La consulta normal lee 1..51. El campo 52 se consulta por separado y se cachea
durante una hora en la capa Ypsilon; no forma parte del contrato genérico de
transporte Runxin.
