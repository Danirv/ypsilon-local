# Perfil Runxin F79D

Este documento recoge el conocimiento del dispositivo F79D usado por Ypsilon. Los ids, codecs y evidencias están en `runxin/fields.py`; `runxin/f79d.py` construye las tramas y decodifica el estado.

## Leyenda de evidencias

- **A** — presente en el codec/campos de la aplicación WaterDevice antigua;
- **O** — valor o comportamiento observado en el Ypsilon/F79D real del proyecto;
- **HW** — escritura local ejecutada de extremo a extremo y confirmada mediante una lectura local independiente;
- **CW** — cambio de valor observado mediante la aplicación cloud antigua.

`A` no implica que todos los firmwares o rebrands F79D implementen el campo de forma idéntica.

## Semántica del patrón de trabajo

La aplicación WaterDevice antigua contiene un enum explícito para el campo 9. Ypsilon expone el mismo mapping como enum de Home Assistant de solo lectura:

| Raw | Estado estable | Etiqueta de la app antigua |
|---:|---|---|
| 0 | `downflow_meter_delayed` | DF Meter delayed |
| 1 | `downflow_meter_immediate` | DF Meter immediate |
| 2 | `downflow_intelligent_meter_delayed` | DF Intelligent meter delayed |
| 3 | `upflow_meter_delayed` | UF Meter delayed |
| 4 | `upflow_meter_immediate` | UF Meter immediate |
| 5 | `upflow_intelligent_meter_delayed` | UF Intelligent meter delayed |
| 6 | `filter_type` | Filter type |
| 7 | `meter_delayed` | Meter delayed |
| 8 | `meter_immediate` | Meter immediate |
| 9 | `intelligent_meter_delayed` | Intelligent meter delayed |

Los códigos 0..6 también son coherentes con las familias publicadas por Runxin para flujo descendente, flujo ascendente y filtro. La integración no expone el campo 9 como escritura: conocer un encoding legacy no basta para considerar seguro un ajuste mecánico.

## Escrituras verificadas en hardware

Confirmadas mediante SET local + lectura local independiente: **4, 6, 7, 10, 43 y 47**. Siguen pendientes **34 (forzar regeneración)** y **49 (modo vacaciones)**.

## Reconstrucción de volúmenes

Los campos 35, 37, 39 y 41 necesitan el campo de continuación inmediatamente posterior:

```text
value = (continuation_high
         + continuation_low * 100
         + base_high * 10000) / 100
```

El byte bajo del campo base no participa en esta fórmula. Para el `waterVolumeUnit = 2` verificado en el proyecto, los valores resultantes se expresan en metros cúbicos. El campo 11 es un valor separado de caudal instantáneo de servicio en centésimas; con el código de unidad 2 se expone en metros cúbicos por hora.

## Regeneración

`regenerationPattern` representa el criterio general de regeneración:

- `0`: por contador / volumen;
- `1`: por tiempo / días.

`workPattern` representa la estrategia concreta del controlador descrita arriba. Por tanto, ambos campos son complementarios y no equivalentes.

En el equipo del proyecto el modo normal es por volumen. `residualWaterProduction` es capacidad de tratamiento restante, no agua almacenada físicamente. `operationDay` y `remainingDay` son principalmente relevantes en el modo tiempo/días.

El payload cloud legacy contiene también `regenerationTimes`, pero no se ha demostrado ningún mapping local F79D. Ypsilon no inventa uno ni expone una entidad local derivada.

## Semántica de estadísticas de Home Assistant

Las clases de estado se asignan según el modelo actual de sensores de Home Assistant:

- `flowRate` — `measurement`: lectura de caudal del momento actual;
- `dailyWaterConsumption` — `total_increasing`: total diario acumulado que puede reiniciarse al comenzar un nuevo ciclo;
- `residualWaterProduction` — `measurement`: capacidad restante actual;
- `averageWeeklyWaterConsumption` — sin `state_class`, porque ya es una agregación histórica;
- `periodicWaterProduction` — sin `state_class`, porque es una cantidad periódica/configurada proporcionada por el controlador y no una medición actual ni un contador acumulativo.

Así se evita pedir a Home Assistant estadísticas a largo plazo engañosas sobre valores ya agregados o de tipo configuración.

## Superficie segura de escritura de Home Assistant

El codec conoce más encodings de los que HA expone. El servicio administrador es deliberadamente más restrictivo. No debe añadirse un campo solo porque la aplicación antigua tenga encoder: una trama sintácticamente válida puede cambiar un parámetro mecánico inseguro.

## Campo 52

La consulta normal lee 1..51. El campo 52 se consulta por separado y se cachea durante una hora en la capa Ypsilon; no forma parte del contrato genérico de transporte Runxin.
